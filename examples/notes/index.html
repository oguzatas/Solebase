Settings

Share

Opens this same origin on another device. Does not install a native app, and does not sync notes by itself — each device keeps its own OPFS vault (Solebase) unless you configure Sync below.

  • Install / Add to Home Screen from the browser menu for an app-like icon (PWA).
  • After the first visit, the service worker + OPFS-backed Solebase vault keep the app usable offline. Losing internet ≠ losing the app once cached.
  • localhost cannot be opened usefully on a phone for E2EE — deploy over HTTPS (GitHub Pages / Cloudflare Pages / Netlify) or a TLS tunnel, then scan this QR. See docs/SHIP.md.

Share to another device

Short-lived QR / link that copies R2 credentials + encryption key into another browser’s localStorage and starts Solebase sync. Encrypted blob on R2 (~20 min TTL); the encryption key stays only in the QR/URL — never plaintext on public R2. Requires Saved R2 keys on this desktop first.

iPhone flow: scan QR → opens Safari → credentials save in Safari → Share → Add to Home Screen → open the Solebase icon → paste/open the same bootstrap link once (or scan again). Safari and the Home Screen app use separate storage.

Short-lived encrypted link (~20 min). Phone Safari imports first; then open the same link once in the Home Screen app.

  • On the phone: scan the QR (or open the link) — no need to re-type keys. Camera scan in-app is optional; the URL is enough.
  • After Safari import, Add to Home Screen, then reclaim with the same link in the home-screen app (empty PWA shows an Import banner).

Solebase sync (R2)

Layer 1 Solebase.init({ sync: { provider: 's3', options } }) — E2EE changeset blobs in Cloudflare R2. Credentials stay in this browser’s localStorage only (never committed).

One dashboard step: Cloudflare dashboard → R2 → Overview → Manage API Tokens → Create → permissions Object Read & Write → apply to bucket solebase-sync-test → copy Access Key ID + Secret Access Key into the fields below. (MCP OAuth cannot mint S3 API tokens; API Tokens Write is required once.)
